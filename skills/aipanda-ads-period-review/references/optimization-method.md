# 从诊断到有条件的优化候选

参考课程与内部复盘笔记的分层处理思路，重新整理为“发现 → 可能解释 → 证据缺口 → 复核候选 → 观察与恢复条件”。这里没有统一暂停线、预算比例、调价幅度或固定恢复天数。

零订单与较高点击只能触发复核。先核归因、相关性、源对象归属、跨来源成交与保护标记；只在显式配置的样本线内讨论完整查询词的精确否定复核。相关或未知的流量不能直接变成否词；商品目标另列排除复核。

有订单但目标 ACOS 偏高时，分别回查历史 CPC、订单 / 点击、流量位置和页面承接等可能原因。历史扣费 CPC 不等于当前 Bid，广告目标成本线不等于盈亏线。当前配置及必要背景未输入时，输出缺证状态，不从统计比率编出绝对调价值。

迁移不能简化为“自动 / 广泛出单就加精确并否掉来源”。先确认声明的承接单元启用、独占归属、匹配类型适用、余量、连续观察与该单元自身样本及效率；来源也要达到复核样本线。来源已有成交、否定表不完整、已有同类否定、范围残差或证据矛盾均保留阻断。满足声明条件只得到 REVIEW_ONLY，仍非后台就绪或执行批准。

相关性、归属、余量和连续承接均是使用者声明，本包不独立证实。输出没有 bid / budget 数值、执行 payload 或上传入口。若另行授权真实业务动作，应在本地重查现状、记录原值、规定单一测试变量与观察 / 停止 / 恢复条件；本公开 Skill 的安装和运行不授权这些动作。

活动带来的短期变化要在恢复阶段复核。没有真实小时数据就不做小时拆分；没有对照与排除替代解释就不说已验证因果。利润核对、采购成本、费用账本与经营资料都不进入本包。
