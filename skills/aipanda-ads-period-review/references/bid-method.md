# 竞价：把历史表现、声明配置与试验假设分开

方法参考经授权的 Apollo / Louis 学习摘要与内部复盘笔记；实现重新编写，未采用课程的建议竞价倍数或固定调幅。

先定位问题来自流量结构、点击竞争、承接还是近期变更，再讨论 Bid。历史 CPC 是报告扣费的比值，不等于当前基础竞价，更不是未来每次点击的价格。广告目标 ACOS 与同口径广告 AOV、订单 / 点击可以形成目标成本 CPC 参考，但不是利润或盈亏线，不能直接填入 Bid。

把当前配置与调用者的提议分别列出，明确这只是候选假设。提高出价需要成熟样本、目标内的观测效率、可承接能力与必要背景；降低出价也不能只因某个参考线更低就机械执行。无订单但点击较多可以触发复核，不证明流量一定无效。

基础出价常在 Keyword / Target 层，预算与广告位调整常在 Campaign 层。不能拿一个 Target 的基础竞价去解释整个混合 Campaign。新数值模型仅支持声明为单一或统一基础竞价的简化活动；混合 Bid、动态策略和其他加价时不计算单一广告位竞拍上限。

固定竞价情景使用 base × (1 + placement_pct / 100)，并标为简化配置情景。它不验证现场状态，不建模受众、日程、Amazon Business、动态或其他调整，不代表实际扣费或保证的拍卖上限。启用任何自动策略前，需另核实际账户支持能力、目标与复盘口径；本 Skill 不替用户启停策略。

试验先选一个可解释的变量，保留原值、提议值、边界、观察窗、归因等待与恢复条件；未隔离共同变化不归因于某次调价。脚本不自动产生推荐价，不包含提交或恢复后台的接口。
