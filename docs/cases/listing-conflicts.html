参数冲突时，先停下那一句。

SKU 与批次绑定，决定参数能否进入 Listing 草稿。

实务中的问题

规格文件、旧页面和 AI 草稿对材质、尺寸或配件数量给出不同答案。直接选择更好卖的参数，会把事实争议带进标题、五点和图片。

本例用虚构收纳箱重构冲突：两份合成资料分别声明 polyester / cotton、宽度 44 / 46 cm。来源标签与 reviewed_original 状态也是输入设定，没有真实文件或商品被公开。

把冲突显式留下

字段合成输入审计结果
body.materialpolyester / cottondisputed
dimensions[44,31,26] / [46,31,26] cmdisputed
included_quantity1 piece，单一当前范围声明confirmed，仅代表输入声明通过规则
标题尺寸句46 cm wide storage bin → SIZE-Bblocked_missing_or_conflicting_evidence

即使 SPEC 在输入中被标成已审阅资料，程序仍保留不同来源的冲突，不替用户选择一个版本。审计总状态为 DRAFT_WITH_BLOCKERS，authenticity_independently_verified=false。

评论的分母也要保留

5 条合成评论去重后为 4 条：目标变体 2、其他变体 1、未知变体 1。样本不完整；主题出现次数不能叫产品缺陷率，更不能直接推算全体买家满意度。

怎样复现

使用 Listing 包的公开练习命令。需要阻断失败码时可额外加 --strict：仍保存 JSON，但因存在阻断返回 2。

合成证据输入实际审计 JSON继续看文意反例 →

怎样用于自己的商品

先找当前 SKU / 批次的原件与实物记录；必要时按部件拆分材质。记录单位、适用范围、审阅人和时间；冲突解决后重新审计，再逐句核对文案。程序只能检查你声明的数据关系，不能鉴定原件真伪。
