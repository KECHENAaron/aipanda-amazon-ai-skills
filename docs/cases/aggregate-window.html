汇总报表，不能长出每日趋势。

没有 date 列时，先承认时间粒度，再讨论搜索词候选。

实务中反复遇到的问题

运营拿到一段时间的搜索词汇总，却习惯要求最近 7、14、30 天的升降趋势。同一张汇总表无法还原各天发生了多少点击和订单。把全部数值分摊或贴上 30d 标签，会制造不存在的证据。

本例将问题改写为虚构收纳箱的 12 天 SP 搜索词报告。品牌、商品、活动、词、日期和数字均重新构造，金额约定为 USD；25% 目标 ACOS 仅是演示配置。

先锁定输入口径

  • 日期范围：2026-09-01 至 2026-09-12；4 条汇总行，无逐日 date 列。
  • 范围：虚构商品 B0DEMO0001，对应示例活动与广告组；不代表全账户或逐订单归因。
  • 转化字段完整是这个合成输入的设定。真实报告还需核对归因成熟度、币种及订单归属。

实际运行结果

字段结果怎样理解
input_modeaggregate保留声明的汇总窗口
observed_daily_datesnull没有声称观测到逐日数据
decision_counts观察 2；放量候选 1；控费候选 1来自启发式规则，尚未具备执行条件
candidate_only / business_writestrue / 0无后台调整

输出仅保留 period 指标，趋势状态为 not_available_aggregate。汇总 ACOS 约 31.65% 是这份合成数据的计算结果，不能据此推断账户盈亏或某次调价效果。

怎样复现

从社区搜索词包目录按 公开练习命令运行，依赖见 requirements.txt。报告展示源投放信息；需要回到具体活动、广告组与目标核验后才能决定动作。

值得借鉴的做法

先区分 daily 与 aggregate，再谈窗口。要求趋势时补逐日明细；资料不足时保留缺口。候选的点击门槛、ACOS 和花费线都应按具体商品经济性校准；历史 CPC 也不能代替当前 Bid。
