引用正确，句子仍然可能错。

一次公开整理，修正了工具容易让人误读的“通过”状态。

这次整理发现了什么

Listing 检查器会确认文案引用的事实 ID 存在、范围匹配且没有冲突。原有输出名 supported_by_declared_evidence 容易被理解成“这句话已经有证据支持”，但程序没有理解句子的含义。

一个能区分对错的反例

事实句子引用
QTY：数量 1Includes one storage binQTY
同一事实Includes ten storage binsQTY

第二句明显与数量 1 不符，但两个句子的事实引用都有效。这说明“引用检查通过”与“文意正确”是两项不同验证。

公开版改了什么

  • 有效引用状态改为 references_validated_manual_text_review_required。
  • 逐句与总结果都明确 text_semantics_verified=false / copy_text_semantics_verified=false。
  • 增加反例测试，确保任意不相关文字不会被输出成已验证文案。
  • 未知或冲突的事实引用仍然阻断。此次改动仅在公开副本中，原安装包保持原样。
这是对输出语义和边界的修正，并未实现自动语义核验。示例仍需人找出“十件”的错误。

怎样复现

运行 test_valid_reference_does_not_verify_arbitrary_copy，再查看合成证据输入中的 COPY-QTY 与 COPY-COUNTEREXAMPLE 两条结果。Listing 包共 9 项测试通过。

可迁移的方法

审阅工具时，为“通过”构造一个仍然错误的反例。状态名应描述实际做过的检查；没有做过的验证应明确保留 false。人工与后续语义检查分别留证，避免扩大自动化能力。
